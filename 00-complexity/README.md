# Complexity

How to tell if code is fast or slow before you run it.
{: .lead}

Every topic on this site says things like "this is O(n)" or "that is too slow". This topic explains what that means, where it came from, and how to work it out yourself. Read it before Hashing.

## How this topic helps you remember

You won't memorize anything here. Each page uses methods that research shows help people remember for a long time:

| What you'll do | Why it works |
|---|---|
| **Guess first.** Each section starts with a question. You guess, then open the answer. | A wrong guess makes your brain pay attention to the right answer. Researchers call this the [pretesting effect](https://featuredcontent.psychonomic.org/test-first-learn-later-the-power-of-pretesting-to-enhance-learning/). |
| **One picture per idea.** O(n²) is a room where everyone shakes hands. O(log n) is cutting a book in half. | A picture and a story are much easier to recall than a formula. Later topics reuse the same pictures. |
| **Measure it yourself.** You run real code and watch it slow down 2× or 4×. | You believe and remember what you saw happen. |
| **Test yourself.** Each page ends with questions you answer from memory. | In a [large review of study methods](https://www.psychologicalscience.org/news/releases/which-study-strategies-make-the-grade.html), testing yourself was one of the two best methods. Rereading was one of the worst. |
| **Review on day 1, 3, 7 and 21.** Each page has a button that tracks this for you. | Spacing reviews out over days was the other top method in that review. |

> Every later step on this site starts with "guess the complexity first". Using it again and again is what makes it stick.
{: .tip}
